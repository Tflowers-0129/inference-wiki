教学构造 / 只计 Dispatch 逻辑数据量

80 次专家任务，需要发出多少份激活？

固定四个 rank，每个 rank 十个 token；每 token 选两位不同专家。E0/E1 在 rank 0，E2/E3 在 rank 1，依次类推。切换目标专家的分布，观察任务数与跨 rank 副本数为什么不同。

逐 token 核对专家与目标 rank

矩阵每格统计一个源 rank 送往一个目标 rank 的激活份数；对角线为本地使用，不计入远端 payload。AllGather 对照让每个目标看到全部输入；定向对照按 token＋目标 rank 去重，同卡两个专家共用一次跨卡传入。真实后端是否采用这种去重，需另查实现。

BF16、H=4096，每份激活为 4096×2=8192 B（8 KiB）。这里只计源到目标的逻辑 Dispatch payload，不含路由元数据、量化尺度、协议、padding、ReduceScatter、Combine、集合通信算法和链路跳数；本地使用也不代表零设备访存。这里不选择引擎算子，也不预测耗时。
