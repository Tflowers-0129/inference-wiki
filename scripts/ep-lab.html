教学构造 / 只计发送到目标 rank 的输入激活

80 次专家任务，需要发出多少份激活？

固定四个 rank，每个 rank 十个 token；每个 token 选两个不同的专家。E0/E1 在 rank 0，E2/E3 在 rank 1，依次类推。切换目标专家的分布，观察任务数与跨 rank 副本数为什么不同。

逐 token 核对专家与目标 rank

矩阵每格是一个源 rank 向一个目标 rank 发送的激活份数。对角线表示本地使用，统计远端数据量时跳过这些格子。AllGather 将全部输入分发给每个 rank。定向发送按 token 和目标 rank 去重：如果两个专家位于同一张远端卡，只需向它发送一份激活。真实后端是否采用这种去重，需另查实现。

BF16、H=4096，每份激活为 4096×2=8192 B（8 KiB）。这里只计源到目标的输入激活数据量，不含路由元数据、量化尺度、协议、padding、ReduceScatter、Combine、集合通信算法和链路跳数；本地专家使用激活时仍需读取设备内存。实际算子和耗时取决于具体实现。
