跟着手册走两次请求

R1同一《手册》· 128 token尾 token ①
R2同一《手册》· 128 token尾 token ②

①、② 是不同的第 129 个 token；每页容纳 128 个位置。

机器 A：P0、P1 各有自己的 HBM。机器 B：D0、D1 各有自己的 HBM。机器 C：共享 Store 的 DRAM。

  1. 初态：C 已存有独立前缀《保修条款》，还没有手册对象 M。
  2. R1 冷算：P0 页 3 放手册 KV，页 4 放尾 token ① 的 KV。
  3. P0 → C（D2rH）：将完整的手册块保存为 M。尾页不存入池。
  4. P0 → D0（D2D）：D0 发起 READ，将本次请求的页 [3, 4] 复制到自己的页 [12, 13]。
  5. C → P1（rH2D）：R2 的本地前缀未命中；从 C 的 M 读到 P1 页 9。
  6. P1 只算新尾：第 129 个 token ② 的 KV 写入页 10。
  7. P1 → D1（D2D）：D1 发起 READ，将本次请求的页 [9, 10] 复制到自己的页 [20, 21]。

M 被读取后仍留在 C；《保修条款》一直不变。每次交接完成后的 HBM 驻留不再跟踪。

这幅图跟踪到哪里？

这是教学示意。M 是手册完整前缀的对象键简称；只画 C 上 1 个可读副本。R2 在 P1 本地未命中，且两个 D 均需接收本次请求的两页。

页号是教学地址。每页包含对应的 K、V；尾页只有 1 个有效位置。只跟踪本次交接前的相关块与交接映射，之后不推断 HBM 页仍驻留或已释放。

先保存 M、再交给 D0 是阅读顺序，两件事没有这个强制先后关系。P1 读 M 则以该副本已可读为前提；后续 Decode 不在图内。
